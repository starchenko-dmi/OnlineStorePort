# Интернет-магазин (Online Store)

Учебный проект интернет-магазина, разрабатываемый в рамках курса по Django.  
Проект постепенно расширяется: от базовой структуры до полноценного веб-приложения с каталогом товаров, корзиной, формами и админкой.  
В результате — готовое портфолио-решение.

## ✅ Реализованные функции

- **Каталог товаров**: отображение списка товаров на главной странице.
- **Детальная страница товара**: переход по клику на название товара открывает страницу с полной информацией (наименование, описание, изображение, цена, категория, даты создания и изменения).
- **Постраничная навигация**: на главной странице реализована пагинация (по 8 товаров на страницу) с удобной навигацией («Первая», «Предыдущая», «Следующая», «Последняя»).
- **Админка**: через Django Admin можно управлять товарами, категориями и контактной информацией.
- **Контактная страница**: отображает данные, введённые через админ-панель, и содержит форму обратной связи.
- **Базовый шаблон**: выделен общий `base.html`, содержащий шапку, подвал, подключение стилей и блоки для наследования (`{% block title %}`, `{% block content %}`).
- **Модульность**: главное меню и другие повторяющиеся элементы легко переиспользуются.
- **Адаптивная вёрстка**: интерфейс корректно отображается на мобильных устройствах благодаря Bootstrap 5.
- **CRUD для товаров**:
  - Создание, редактирование и удаление товаров реализованы через формы Django.
  - Добавлена **кастомная валидация**:
    - Название и описание товара **не могут содержать запрещённые слова**:  
      `казино`, `криптовалюта`, `крипта`, `биржа`, `дешево`, `бесплатно`, `обман`, `полиция`, `радар` (проверка без учёта регистра).
    - Цена не может быть **отрицательной** (валидация через `clean_price`).
  - Формы стилизованы с помощью переопределения метода `__init__` для соответствия общему дизайну (поля получают класс `form-control`, кнопки — `btn btn-success` и т.д.).
- **Система пользователей**:
  - Создано отдельное приложение `users`.
  - Реализована **кастомная модель пользователя** на основе `AbstractUser` с авторизацией по **email**.
  - Добавлены дополнительные поля: **аватар**, **номер телефона**, **страна**.
  - Реализованы:
    - **Регистрация** с отправкой приветственного письма.
    - **Авторизация** по email и паролю.
    - **Защита маршрутов**: только авторизованные пользователи могут **создавать, редактировать и удалять товары**.  
      Страница просмотра списка товаров остаётся **публичной**.

## 🔒 Система ролей и разрешений (реализовано в рамках заданий)

### 🛡️ Модерация товаров
- В модель `Product` добавлено поле `is_published` (`BooleanField`, по умолчанию `False`), управляющее публикацией товара.
- Добавлено кастомное разрешение: `can_unpublish_product` — может снимать товар с публикации.
- Создана группа **«Модератор продуктов»** через кастомную команду `create_moderator_group`.
- Группе назначены права:
  - `catalog.can_unpublish_product`
  - `catalog.delete_product`
- В шаблонах и представлениях реализована проверка:
  - Только модератор может **снимать товар с публикации** (если он опубликован).
  - Модератор **может удалять любой товар**.

### 👤 Владение товарами
- В модель `Product` добавлено поле `owner` (`ForeignKey` к пользователю).
- При создании товара его `owner` автоматически устанавливается в текущего пользователя.
- Реализована логика доступа:
  - **Редактировать** товар может **только его владелец**.
  - **Удалять** товар могут **владелец ИЛИ модератор**.
- В шаблонах кнопки отображаются условно:
  - «Редактировать» — только владельцу.
  - «Удалить» — владельцу или модератору.

### ✍️ Управление блогом
- Создано приложение `blog` с моделью `BlogPost` (заголовок, содержание, превью, дата, статус публикации, счётчик просмотров).
- Реализованы представления: список, детали, создание, редактирование, удаление.
- Создана группа **«Контент-менеджер»** (через кастомную команду `create_content_manager_group`).
- Группе назначены права: `add_blogpost`, `change_blogpost`, `delete_blogpost`.
- Обычные пользователи видят только **опубликованные** записи.
- Управление записями (CRUD) доступно **только контент-менеджерам** — модераторы из других отделов (например, товаров) **не имеют доступа**.
- URL-структура блога: `/blog/`, `/blog/post/1/` и т.д.

## 📁 Структура проекта

- `catalog/` — основное приложение для отображения каталога товаров, домашней и контактной страниц.  
  - `models.py` — модели `Product`, `Category`, `ContactInfo`.  
  - `views.py` — контроллеры для главной страницы, деталей товара, контактов.  
  - `forms.py` — формы с валидацией и стилизацией.  
  - `urls.py` — маршруты приложения.  
  - `templates/catalog/` — шаблоны страниц.  
- `blog/` — приложение для управления публикациями в блоге.  
  - `models.py` — модель `BlogPost`.  
  - `views.py`, `urls.py`, `templates/` — полный CRUD-цикл с защитой по ролям.  
- `users/` — приложение для управления пользователями.  
  - `models.py` — кастомная модель пользователя.  
  - `forms.py` — форма регистрации.  
  - `views.py` — представления регистрации и входа.  
  - `templates/users/` — шаблоны форм.  
- `config/` — настройки Django-проекта (`settings.py`, `urls.py` и др.).
- `static/` — статические файлы (CSS, JS, изображения), включая Bootstrap.
- `media/` — загружаемые пользователем файлы (изображения товаров, аватары).
- `manage.py` — утилита управления проектом.

## 🛠 Технологии

- **Python** 3.11+
- **Django** 5.2+
- **Bootstrap 5** — для адаптивной вёрстки
- **Poetry** — управление зависимостями и виртуальным окружением
- **PostgreSQL** — основная СУБД (с возможностью переключения на SQLite для разработки)
